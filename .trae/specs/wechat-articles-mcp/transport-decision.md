# 微信文章 MCP 传输协议决策

## 1. 传输协议选择

**选择的传输协议：STDIO**

## 2. 选择理由

### 2.1 使用场景分析

**主要使用场景**：
- 本地开发和测试
- 与 Claude Desktop 集成
- 个人研究和内容分析
- 单用户操作

**部署环境**：
- 主要在本地机器运行
- 不需要远程访问
- 无需多用户并发

### 2.2 STDIO 优势

1. **简单部署**：
   - 无需网络配置
   - 无需端口管理
   - 无需防火墙规则

2. **本地集成**：
   - 与 Claude Desktop 完美集成
   - 本地文件系统访问
   - 低延迟通信

3. **安全性**：
   - 无需暴露网络端口
   - 本地进程间通信
   - 减少攻击面

4. **开发便利**：
   - 快速调试和测试
   - 简化开发流程
   - 便于本地验证

### 2.3 Streamable HTTP 不适用原因

1. **无远程访问需求**：
   - 微信文章获取主要是个人使用
   - 不需要多客户端访问
   - 不需要Web服务集成

2. **复杂性增加**：
   - 需要网络配置
   - 需要端口管理
   - 增加部署复杂度

3. **性能考虑**：
   - HTTP协议开销
   - 网络延迟
   - 额外的序列化/反序列化

## 3. 部署配置

### 3.1 STDIO 配置

```json
{
  "mcpServers": {
    "wechat-articles": {
      "command": "python",
      "args": ["main.py"],
      "env": {
        "PLAYWRIGHT_BROWSERS_PATH": "0"
      }
    }
  }
}
```

### 3.2 环境变量

- `PLAYWRIGHT_BROWSERS_PATH`：Playwright 浏览器路径（可选）
- `WEIXIN_CRAWLER_TIMEOUT`：爬虫超时时间（默认30秒）
- `WEIXIN_CRAWLER_RETRY_COUNT`：重试次数（默认3次）
- `WEIXIN_CRAWLER_HEADLESS`：是否无头模式（默认true）

### 3.3 依赖管理

- Python 3.8+
- Playwright
- BeautifulSoup4
- MCP Python SDK
- requests

## 4. 扩展性考虑

### 4.1 未来可能的协议升级

如果未来需求变化，可考虑升级到 Streamable HTTP：

**触发条件**：
- 需要远程访问
- 多用户并发需求
- Web服务集成需求
- 负载均衡需求

**迁移路径**：
- 保持API兼容性
- 逐步迁移配置
- 支持双协议运行

## 5. 网络配置要求

### 5.1 当前配置（STDIO）
- 无需网络配置
- 本地进程通信

### 5.2 未来配置（Streamable HTTP）
- 默认端口：8080
- 主机：localhost
- 路径：/mcp
- CORS配置

## 6. 决策总结

**选择 STDIO 的理由**：
1. ✅ 主要用于本地开发和测试
2. ✅ 与 Claude Desktop 集成
3. ✅ 单用户场景
4. ✅ 不需要网络访问
5. ✅ 简化部署和维护

**不选择 Streamable HTTP 的理由**：
1. ❌ 无远程访问需求
2. ❌ 无多用户并发需求
3. ❌ 增加不必要的复杂性
4. ❌ 当前场景下无性能优势

## 7. 验证场景

### 7.1 本地测试
- Claude Desktop 集成测试
- 命令行工具测试
- 错误处理测试

### 7.2 性能验证
- 响应时间 < 10秒（考虑到浏览器启动和页面加载）
- 内存使用合理（浏览器实例管理）
- 稳定性测试（反爬虫规避）

---

**结论**：基于微信文章MCP的使用场景和需求，STDIO是最合适的传输协议选择。
